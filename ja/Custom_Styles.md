## カスタムスタイルを使用する [using-custom-styles]

![][img1]

  [img1]: images/custom_styles.jpg @2x width=544px height=196px class=center

カスタムスタイルを探す一番簡単な方法は、[カスタムスタイルギャラリー][2]を利用することです。ここでは公開されているスタイルの動作を確認したり、ボタン一つでインストールしたり、さらには[自作のスタイルを投稿][6]して登録してもらったりすることができます。

ローカルドライブにあるカスタムスタイルシートをMarkedに追加するには、{% prefspane Style %}を使用します。追加した新しいスタイルは、ウインドウ設定やそれぞれのウインドウにあるドロップダウンメニューに追加され、追加したCSSファイルのベースファイル名にもとづいて名前が付けられます。カスタムCSSファイルはドライブ内の安全な場所に保管してください。ファイルの場所を移動すると、新しい場所から再度追加するまでMarkedから削除されます。Markedで使用しているCSSファイルを削除または名前変更する前には、開いているドキュメントを閉じて、設定からそのスタイルを削除しておくことをおすすめします。そうしなくても問題が起きるわけではありませんが、混乱を避けられます。

カスタムスタイルは、スタイルマネージャの追加ボタンを使うか、1つ以上のCSSファイルを設定パネルにドラッグすることで追加できます。

## スタイルマネージャでスタイルを管理する [managing-styles-with-the-style-manager]

スタイルマネージャを起動すると、組み込みスタイルとカスタムスタイルのすべてを1か所でまとめて管理できます。{% prefspane Style %}パネルにある**スタイルを管理…**ボタンをクリックするか、環境設定ウインドウにCSSファイルをドロップするだけでOKです。Markedがファイルをインポートしてスタイルマネージャを開き、新しく追加された行を自動的に選択します。CSSファイルをスタイルマネージャのウインドウに直接ドラッグすることもでき、複数のファイルをドラッグすると、オーバーレイの表示が「N個のカスタムスタイルを追加」に変わり、まとめてインポートしていることがひと目でわかります。

![][img-style-manager]

スタイルマネージャの中には、組み込みスタイルとカスタムスタイルが混在した並べ替え可能な表があります。各行には以下の項目があります。

- **有効**チェックボックス：オン/オフを切り替えると、スタイルメニュー、デフォルトスタイルのポップアップ、キーボードショートカットに即座にスタイルが追加・削除されます。現在使用中のスタイルを無効にすると、自動的に次に使用可能なスタイルに切り替わります。
- **名前**列：その場で編集でき、変更内容は保存されてすべてのメニューに反映されます。スタイル名をクリックすると、その場で編集できます。
- **ソース**列：組み込み、カスタム、複製のいずれであるかが表示されます。
- **アクション**：**編集**（CSSファイルをエディタで開く）、**複製**（コピーを作成し、ディスク上に新しいCSSファイルを作成する）、**Finderで表示**（ファイルをFinderで表示する）、**削除**（参照のみを削除するか、CSSファイルをゴミ箱に移動するかを選択可能）の各ボタンが並んでいます。

行はドラッグ&ドロップで並べ替えることができ、その順序はスタイルメニューだけでなく`⌘/#`のショートカット割り当てにも反映されます。つまり、スタイルを好きな位置にドラッグするだけで、思いどおりの順番に配置できるということです。外部のCSSファイルを特定の位置にドラッグすることもでき、ドロップ位置を示すインジケーターによって新しいスタイルの挿入場所が決まります。

### ライブプレビュー [live-preview]

右側のペインには、見出しやリスト、表、コードブロックなど一通りの要素を含んだHTMLドキュメント全体の中で、選択したスタイルをレンダリングするプレビューが表示されます。プレビューにはディスク上の実際のCSSが使用されるため、外部エディタで編集した内容が即座に反映されます。チェックボックスでダークモードプレビューの切り替えもできます。

そのほかのスタイル（や、自作のスタイルを作る際の参考例）は[GitHub][1]で見つけることができます（どんなものがあるかざっと確認するには[サンプル][2]を参照してください）。詳細やコツについては[カスタムCSSの作成][3]を参照してください。

## 追加CSS [additional-css]

{% prefspane Style %}には、「追加CSS」という項目があり、「CSSを編集」というボタンがあります。このボタンをクリックすると、すべてのスタイルに適用される汎用的なCSSルールを追加できるウインドウが開きます。Markedのデフォルトスタイルの一部を上書きする際には、ルールの詳細度（specificity）が重要になる場合があるので注意してください。ドキュメントの本文全体は、idが「#wrapper」であるdivで囲まれています。セレクタの先頭にこれを付けることで、より簡単に上書きできるようになります。例：

    #wrapper img { width: 100%; height: auto; }

このフィールドに書いたCSSは、**現在使用中のテーマに追加されるかたち**で適用されます。これは完全なカスタムスタイルの代わりにはなりません。このフィールド専用に書かれたスタイルシートは意図的に部分的な内容になっているため、これをスタイルマネージャからテーマとして読み込むと、カバーされていない部分はすべてスタイルが適用されない状態になってしまいます。

Markedは追加CSSのセレクタを、適用前に**書き換え**ます。`.mkprinting`のような先頭のbodyクラスは、`#wrapper`の下にネストされるのではなく、`body`にマージされます。そのため、このフィールドの印刷用ルールには`body.mkprinting #wrapper …`を使用してください（書き換えルールの詳細については[カスタムCSSの作成](Writing_Custom_CSS.html#additional-css-settings)を参照してください）。このフィールドにはサイズ制限や妥当性チェックはありません。無効なCSSは単に効果を持たないだけです。

このフィールドのCSSは、使用しているスタイルに関係なくすべてのドキュメントに適用されます。スタイルを含めてHTML書き出しを行う場合も同様です。条件に応じてカスタムCSSを適用したい場合は、{% prefspane Processor %}のカスタムルールにある「スタイルを設定」「CSSファイルを挿入」「CSSを挿入」アクションを使用してください。

## 印刷とPDF書き出し [print-and-pdf-export]

Markedはすべてのプレビューに、組み込みの`@media print`ブロック（`mkprintstyles`）を挿入します。これにより、`html`、`body`、`#wrapper`に**10pt**のベースサイズなどのデフォルト値が設定され（{% prefspane Export %}の**書き出し/印刷用のカスタムフォントサイズ**が有効な場合はそのサイズが使用されます）、また`p { font-size: 1em; }`と`li p { font-size: 1em; }`によって段落テキストが正規化されます。これにより、`p { font-size: 1.1429em; }`のような画面専用のルールが、PDFや印刷出力の本文サイズを不必要に大きくすることがなくなります。

PDF書き出しでは、生成に使用される非表示のWebViewで**print**メディアまたは**screen**メディアのいずれかが使用されます。組み込みテーマは通常printメディアを使用しますが、**カスタムスタイル**や[Fountain](Fountain_for_Screenwriters.html)形式のドキュメントでは、レイアウトをプレビューと一致させるためにscreenメディアが使われることがよくあります。つまり、PDF書き出し時に`@media print { ... }`のルールが必ず適用されるとは限らないということです。

PDFおよび印刷/PDFプレビューのスタイルを確実に適用するには、書き出し時にMarkedが`<body>`に追加する`mkprinting`クラスをセレクタの先頭に付けてください（詳細と例については[カスタムCSSの作成](Writing_Custom_CSS.html#printstyles)を参照してください）。**カスタムスタイル**ファイルでは`.mkprinting`単体を使用できます。**追加CSS**では、このフィールドがセレクタを書き換えるため、body付きの形式である`body.mkprinting #wrapper …`を使用してください。両方の経路をカバーする必要がある場合は、どちらの形式も`@media print`と組み合わせることができます。

Markedの印刷用デフォルトと異なるサイズを設定したい場合は、カスタムCSS（または追加CSS）に明示的なルールを追加してください。Markedが挿入する印刷用スタイルを上書きする必要がある場合は`!important`を使用します。例：

```css
@media print {
  #wrapper p,
  body p,
  p {
    font-size: 9pt !important;
    line-height: 1.4 !important;
  }

  h1 {
    font-size: 16pt !important;
  }
}

/* Custom Style (and most theme stylesheets) */
.mkprinting #wrapper p,
.mkprinting body p,
.mkprinting p {
  font-size: 9pt !important;
  line-height: 1.4 !important;
}

.mkprinting h1 {
  font-size: 16pt !important;
}

/* Additional CSS field (selector rewriting) */
body.mkprinting #wrapper p,
body.mkprinting p {
  font-size: 9pt !important;
  line-height: 1.4 !important;
}

body.mkprinting #wrapper h1,
body.mkprinting h1 {
  font-size: 16pt !important;
}
```

`!important`を含まないルールは、`mkprintstyles`内の後続のルールや、印刷時にも適用される、スタイルシート内の他の限定なしセレクタに負けてしまうことがあります。印刷専用の調整は（画面用ルールのみに書くのではなく）`@media print`や`.mkprinting`／`body.mkprinting`のルールにも記述しておくと、プレビューと書き出しの挙動を把握しやすくなります。

## CSSの変更を監視する [watching-css-changes]

{% prefspane Style %}のカスタムスタイルセクションにあるチェックボックスをオンにすると、編集中のMarkdownファイルに加えて、現在使用中のCSSファイルもMarkedが監視するようになります。どちらかのファイルに変更が検出されると、プレビューが更新されます。これは、いちいち手動で更新しなくてもカスタムスタイルを編集できるので便利で、簡単なWeb開発作業にも活用できます。

この機能は、基本的なWebデザイン作業やCSSの試行錯誤(カスタムスタイルの作成など)にも役立ちます。スタイルを適用したいマークアップを含むMarkdownファイルを読み込み、カスタムスタイルを作成して、編集しながらプレビューがリアルタイムに変化する様子を確認してみましょう。

## カスタムCSSを書く [writing-custom-css]

CSSに詳しい方であれば、Markedで使用する独自のスタイルシートを作成できます。詳細は[カスタムCSSの作成][3]を参照してください。新しいスタイルを作成したら、ぜひ[ギャラリー][2]に[投稿][6]して、ほかのユーザーと共有することを検討してみてください。その際は、ガイドに記載されている基本事項を必ず満たし、先頭にメタデータコメントを含めるようにしてください。

[Style Stealer][4]を使えば、既存のWebサイトをもとにスタイルを自動生成することもできます。Webページを読み込んで、Markdownに登場する主要な要素すべての算出スタイルを取得し、それをカスタムスタイルとして保存できます。
